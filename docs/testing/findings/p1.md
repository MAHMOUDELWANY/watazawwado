## P1-001 · Medium · AUTH-12, all student pages · S P · any device, local only · fixed
Local servers (any `NODE_ENV` other than production) gave **every** signed-in learner mock data instead of the
database: `GET /api/student/me` returned the session's raw profile, `PATCH /api/student/me` and
`POST /api/student/onboarding` returned success without saving, `GET /api/student/bookings` returned nothing.
The mock branch keyed on `(!isProd && req.studentUser?.studentProfile)`, true for every real account.
- Steps: start a local server, sign in as a real account, finish onboarding, reload.
- Expected: onboarding saved. Actual: nothing written; the portal kept the trigger's default row.
- Impact: production unaffected (NODE_ENV=production on Vercel), but every local test of a real account was testing mock data.
- Fix: `isDevStudentRequest(req)` (api/index.ts, after `devStudentProfiles`): only a dev token gets the mock path.
  Test: `test/p1-testing-foundation.test.ts`.

## P1-002 · Medium · AUTH-02, ADM-03, TCH-02 · P T A · desktop + phone, AR + EN · fixed (owner decided 2026-11-10: no teacher)
A family account's own row (the parent who does not learn, `booking_preference = 'child'`) is routed to a teacher at
onboarding like a learner. With no teacher picked it goes to the first teacher of the guardian's gender (it went to a
real teacher, Ustadha Afnan, before the QA script passed `teacherId`). The row then shows in that teacher's
"My students" and in the admin list as a learner card labelled "child".
- Steps: sign up as a family without picking a teacher for the parent; open `/dashboard/students` as admin.
- Expected: the parent row has no teacher and is not a learner card (or is shown as "Family account").
- Actual: `assigned_teacher_id` set; card "QA Parent P1 · طفل" with a teacher. Screenshot: `shots/p1/after-P1-005-admin-students.jpg` (QA Parent P1 card).
- Suspected: api/index.ts `POST /api/student/onboarding`, `studentUpdate.assigned_teacher_id = routedTeacher.id` runs
  for the parent row even when `guardianLearns` is false; `/api/dashboard/students` lists it.
- Owner decision 2026-11-10: a parent who only follows their children has no teacher.
- Fix: onboarding routes the parent row only when it is a learner (`selfLearner`: adult account or `guardianLearns`);
  the response no longer reports a routed teacher for a following parent. With no teacher the row leaves teacher
  rosters and opens no extra chat thread. Production data: the one existing row ("noor khan", 2 children, no
  bookings of its own) had `assigned_teacher_id` = Ustadh Mahmoud; cleared. Test: `test/p1-testing-foundation.test.ts`;
  live check: QA Parent P1 created after the fix has no teacher, the children keep theirs.

## P1-004 · Low (to confirm in P4) · display time zone · S P T · same browser, several accounts
After switching accounts in the same browser, the teacher dashboard showed lessons in the previous account's
display zone ("New York / Miami / Atlanta" for a teacher whose hours are in Cairo). The display-zone choice is kept
per browser, not per account. Screenshot: `shots/p1/pane-teacher-dashboard.jpg`. Suspected: the device-time banner's
localStorage key is not scoped by user. Proposed: scope the stored choice by user id, or clear it on sign-out.

## P1-005 · Medium · ADM-03, TCH-02 · A T · desktop + phone, AR + EN · fixed
`GET /api/dashboard/students` selected `id` from `teacher_accounts`, which has no `id` column, so the query failed
silently and every learner card showed "Teacher: TEACHER" instead of the teacher's name (production too).
- Screenshots: before `shots/p1/before-P1-005-admin-students.jpg`, after `shots/p1/after-P1-005-admin-students.jpg`.
- Fix: names by email from `teacher_accounts`, auth ids from `profiles` (api/index.ts, `/api/dashboard/students`).
  Test: `test/p1-testing-foundation.test.ts` (failed before the fix).
