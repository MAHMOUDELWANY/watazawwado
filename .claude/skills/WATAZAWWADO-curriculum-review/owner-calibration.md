# Owner calibration

Read before every review and give it to every expert. Update it in the same session whenever the owner comments on a
report. Dates are the owner's.

## Standing brief (owner, 2026-11-14)
- Harsh, analytical, no courtesy; constructive: every flaw with its fix.
- A report that is not specific, or reads like ordinary talk, is a failed report.
- Visual examples he gave: a code-drawn character with a neck too long, a part sticking out of the drawing, elements
  not sitting together, one thing covering another when the slide changes, delay, lag, glitches, bugs.
- Content examples he gave: storytelling that does not hold together; a later lesson that never says "as we mentioned in
  Lesson 1" (the whole curriculum should be one web in the learner's mind); language too hard for the age; wrong
  information; writing that is simply not good.
- The examples are starting points: experts are expected to go further.
- No AI slop in the visuals.

## Standing brief, additions (owner, 2026-11-21)

- Every review leaves Markdown files in the repo (records, the Arabic report, the run file with decisions), so any
  later session knows exactly where the review stands. On 2026-11-21 a new session could not find the 2026-11-17
  review because it lived on an unmerged branch and the report only as an Artifact: never again.
- The panel works as a team, as in the Zad Adults run; improvements that give a better result are welcome.
